# V1.0: Playback core

Local playback from a terminal, no UI. `cargo run -p aether-cli -- <folder>`.

## What was built

- `common`: `Player` trait, `PlayerError`, `PlayerStatus`, `Track`, `MockPlayer` for tests
- `metadata`: recursive folder scan, tags read with lofty, sensible fallbacks for missing tags
- `audio`: `LocalPlayer` on rodio 0.22
- `core`: `Queue`, `PlaybackController`, ticker thread for auto-advance
- `apps/cli`: scan, queue and play from the terminal

## Decisions

- **Dedicated audio thread.** The device handle isn't `Send`, so `LocalPlayer` talks to a thread that owns all rodio objects, which keeps `LocalPlayer` `Send + Sync`.
- **`load` added to the trait.** Without it nothing says what to play.
- **`next`/`prev` live in the controller.** `LocalPlayer` returns `NotSupported` because it has no queue.
- **`Arc<dyn Player>` in the controller**, so tests keep a handle to the mock and the ticker can share the controller.
- **`tick()` is a plain method.** The ticker thread only calls it every 500 ms, so auto-advance is testable without threads.
- **Queue ends:** `next` on the last track does nothing; `prev` after 3 s restarts the track.

## Known limitations

- `.mpeg` files aren't scanned or played yet.
- Seeking depends on the format and rodio's decoder.
- After a track finishes, `play()` doesn't restart it.
